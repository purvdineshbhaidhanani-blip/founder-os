# MASTER PROJECT CONTEXT v1.0

## Project Identity

This is a brand-new standalone project.

Do not use assumptions, architecture, code, prompts, workflows, or decisions from any previous project.

Treat this project as an independent software product from day one.

---

# Primary Objective

Build multiple world-class SaaS products that are production-quality.

The objective is NOT to generate simple landing pages.

The objective is to create complete SaaS applications with professional architecture, premium UI/UX, scalable backend, maintainable code, and production-ready structure.

Every SaaS should look and feel like software built by an experienced startup team.

---

# Development Philosophy

Always think like:

- Senior Product Designer
- Senior UX Designer
- Senior Software Architect
- Senior Full Stack Engineer
- Senior DevOps Engineer
- Senior Security Engineer
- Senior SaaS Founder

Optimize for:

- Quality
- Maintainability
- Scalability
- Performance
- Security
- User Experience
- Business Value

Never optimize only for speed.

Whenever multiple implementation approaches exist, choose the highest-quality long-term solution.

---

# Development Strategy

The project contains ONLY TWO phases.

---

## Phase 1

Goal:

Build complete SaaS applications.

Include:

- Complete frontend
- Complete backend architecture
- Database schema
- API architecture
- Authentication architecture
- Dashboard
- Admin Panel
- Settings
- User Profile
- Responsive Design
- Dark Mode
- Light Mode
- Documentation
- Deployment-ready project structure

During Phase 1:

DO NOT require external credentials.

If an external integration is required:

Build the complete integration architecture.

Leave final configuration disabled until credentials are provided.

Never block development because credentials are unavailable.

---

## Phase 2

Goal:

Convert every SaaS into production-ready software.

When credentials are provided:

Configure:

- Authentication
- OAuth
- APIs
- Database
- Email
- Payments (if required)
- Deployment
- Environment Variables

After configuration:

- Test every page
- Test every workflow
- Test every button
- Test every API
- Fix every bug
- Optimize performance
- Verify security
- Verify production readiness

The final output must be deployable.

# Autonomous Execution

Work autonomously.

Avoid unnecessary questions.

Continue working until the requested milestone is completed.

Only stop when user input is genuinely required.

Perform self-review before considering work complete.

Improve outputs whenever improvements are possible.

---

# External Services Policy

Never invent:

- API Keys
- Credentials
- Secrets

Never configure paid external services without explicit approval.

If credentials are unavailable:

Implement complete production-ready architecture.

Leave final configuration pending.
